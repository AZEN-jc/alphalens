ALPHALENS / 阿尔法透视镜

散户 vs 主力资金博弈全景终端 · 毕业设计说明书
交付形态：零依赖静态单页 · 双击 index.html 可运行 · 断网可用
技术栈：原生 HTML / CSS / JavaScript（零框架、零 CDN）· Python 3 + AKShare 数据生成层
数据基准：2026-11-13 收盘快照 · 三只标的 × 48 交易日 · 核心自检 59 条断言全过

1 问题定义与目标

散户看盘普遍卡在两个地方。第一是只看涨跌、看不到资金结构，容易把主力的拉高派发误读成突破，或在吸筹阶段被震出局。第二是财报术语门槛高，净资产收益率、净现比、商誉占净资产比重这些指标，很难直接翻译成可执行的判断。市面上的数据终端要么依赖实时网络，答辩现场断网或收盘之后即刻失效；要么把代理指标包装成实盘行情，结论看着专业，被追问一句口径就露馅。

本设计的目标，是交付一个断网可跑、四面板可现场操作的静态终端：覆盖量价透视、大盘温度与板块热力、期指期权先行雷达、财报傻瓜体检；支持逐帧离线回放、深链定位、姓名学号水印与打印电子签章；算法可被断言实证，数据口径在投屏上可见，仿真与真实数据不互相冒充。

2 设计约束与技术取舍

硬约束来自答辩场景：现场网络不可靠，不能依赖 CDN 或实时接口；必须在普通浏览器里双击打开；不能装包、不能配环境。由此确定快照优先架构——实时 AKShare 接口退化为可选的数据生成层，界面与算法层只认一个注入入口 window.AlphaLens.load(snapshot)。渲染层与数据层靠这一份契约解耦，换数据源不需要改一行渲染代码。

视觉锁定 Tactical Telemetry 单一原型：暗色 CRT 基底、等宽字、刚性栅格、无圆角，红涨绿跌。绿色只用于行情数值与曲线，不进入按钮、边框或标题，避免颜色语义被污染。四档资金净额严格守恒，主力累计与散户累计互为镜像，从图上就能看出钱从哪来、到哪去，而不是靠一句说法。

3 系统总体架构

系统自下而上分为五层，依赖方向单向。数据生成层负责抓取与缓存，输出一份结构固定的快照；注入层把快照写进自包含页面，并补上投屏可见的数据口径披露；核心引擎完成校验与全部指标计算；渲染层只消费引擎输出，负责四面板、回放与签章。任一层出错都不会静默穿透到上一层，校验在入口处直接抛错。

4 数据层与口径披露

数据生成脚本把抓取任务拆成十二个最小缓存单元：指数、板块、衍生品、三只标的的日线与财报、以及其中一只标的的真实四档资金。每个单元独立抓取、独立落盘、独立回退。东财 push2his 的四档资金能返回真实响应，但 Python 客户端的 TLS 指纹被服务端拒绝，改用系统 curl 子进程取回原始 klines 再解析，绕过了误判。600519 的四档资金 48 帧全部非零，主力累计净额约正 11.46 亿元；另外两只标的的资金为量价代理值，已在元数据里逐条标注。

代理字段不藏在代码注释里，而是走完整披露链：写入 meta.proxies，命令行同步打印，注入页再插一条投屏可见的口径条。运行时把「PCR」改写为权利金比代理，把「隐波」改写为 20 日已实现波动率，把「万手」改写为万股。这样即使老师现场追问口径，页面上也能直接指给人看。冻结的 index.html 保持零改动，所有修正都发生在注入脚本里。

5 核心算法

所有指标计算集中在 core.js，入口是 computeAll，内部按六个函数展开。资金序列 fundSeries 把四档净额按主力（超大单加大单）与散户（中单加小单）聚合成两条累计曲线，每帧强制四档之和为零，再用六帧斜率加量比识别吸筹与派发：价格横盘、主力斜率超阈值且散户流出记为吸筹；价格拉升超过百分之一点二、量比大于一点五五且主力流出记为派发，同类信号间隔不少于九帧。量价雷达 volumeRadar 用末帧成交量与前五帧均量之比判断底部放量、高位缩量、天量见天价与放量下跌四种形态。

市场温度计 temperature 由涨跌家数比、涨跌停比、封板稳固度、成交额增减四项加权，权重分别为零点三五、零点二五、零点二、零点二，映射到冰点期到过热期五个区间并给出仓位建议。财报体检 scoreReport 把盈利能力、成长潜力、现金流含金量、财务安全性、运营管理效率五维线性归一化后取均分，按七十五、五十五、三十五分为 A/B/C/D 四级，再叠加净现比、商誉占比、短债覆盖等红绿灯规则。衍生品雷达 derivSignals 用基差环比是否超过正负六点判断多头抢跑或贴水扩大，期权侧在注入页明确标注为权利金比代理。板块热力 treemap 采用行贪心布局，板块数较少时宽高比会漂移，但换来实现简单、无外部依赖。

6 功能模块

四个面板各自回答一个具体问题。面板一量价透视，用 K 线主图、主力与散户累计剪刀差、四档资金柱状与吸筹派发标记，回答「谁在买、谁在卖」。面板二大盘温度与板块热力，用四项加权温度计、五档仓位建议和按成交额铺开的板块矩形树图，回答「现在该重仓还是空仓、钱在往哪个板块走」。面板三期指期权先行雷达，用 IF、IC、IM 的基差与环比风向、商品主力对板块的联动、期权代理指标，回答「机构是在抢跑还是对冲」。面板四财报傻瓜体检，把五维评分、等级与红绿灯规则压成一张卡，回答「这家公司赚的是不是真钱」。

公共能力横跨四个面板：48 帧滑块与自动播放支持逐帧回放；深链参数可直接定位面板、标的与帧号；姓名学号水印随输入实时更新并写入本地存储；打印时生成电子签章与免责声明。顶部常驻快照状态标识，明确告知当前是仿真快照还是真实收盘快照，不出现实盘字样。

7 实证结果

自检脚本以零依赖 Node 实现，共 59 条断言，覆盖非法快照拒绝、四档零和、有限性、短帧回放、基差渲染契约等，实测失败数为零。独立验证器做了对抗复核：从真实快照派生十三组变异，Node 与 Python 两侧各自判定，结果十三组全部一致、分歧为零，上一轮的三组契约分歧已全部消除。投屏侧用无头 Chrome 对四个面板逐一取 DOM，披露条每面板命中一次，权利金比、隐波、万手等旧措辞在可见区域均为零处，未出现未定义值或非数值。

数据侧以 2026-11-13 收盘为基准，三只标的各 48 帧。600519 四档资金 48 帧全部非零，主力累计约正 11.46 亿元；财报体检命中真实净资产收益率三年 32.5、36.0、34.2，综合得分 74.2，评级 B；板块净额取同花顺行业资金，半导体净流出约 127.44 亿元；指数与基差为真实值。离线重建从缓存读出十二段，其中十段命中缓存、两段走回退，网络请求计数为零，关键字段与原快照逐字段一致。

工程取舍：四档净额守恒是硬不变量，不能为了曲线好看而放宽；代理值集中在元数据并在投屏披露，不冒充实盘；index.html 作为冻结源文件零改动，所有适配都放在注入脚本，换来数据层与渲染层的彻底解耦。

8 局限与结论

本设计仍有三处已知局限。第一，期权侧没有真实的成交量认沽认购比与隐含波动率数据源，页面展示的是权利金比代理与二十日已实现波动率，只能作情绪参考，不能作为方向性结论的唯一依据。第二，300750 与 002027 的四档资金为量价代理，不是真实的单笔委托分档，已在页面和元数据双重标注。第三，未制作桌面安装包，答辩以双击静态页面交付，这样最稳也最省事。

总体看，系统把散户最关心的四个问题压缩进一个断网可跑的页面，用严格的数据契约和双重校验保证口径一致，用可见披露替代模糊话术。四张工程图分别交代了架构、数据、功能与算法，59 条断言和独立复核给出了可复现的实证。作为毕业设计，它既能在现场被直接操作，也能在被追问实现细节时逐层展开，达到了设计目标。
